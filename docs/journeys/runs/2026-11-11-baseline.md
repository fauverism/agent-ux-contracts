The verify command, run exactly as returned
(`node --import tsx --import ./setup-dom.mjs --test InterruptionCancel.test.tsx`),
in a fresh `npm init -y` project with the listed dependencies installed:

| Consumer `tsconfig.json` | Result |
| --- | --- |
| none | 13 of 13 fail, `ReferenceError: React is not defined` |
| `"jsx": "preserve"` | 13 of 13 fail, same error |
| `"jsx": "react-jsx"` | 13 of 13 pass |

`"jsx": "preserve"` is what this repository's own Next.js site uses
(`site/tsconfig.json`). Nothing in the tool response mentions the
requirement. The pattern page says the runner "needs `jsx: react-jsx`, which
any React project already sets"; this repository's site is a counterexample.

Dependency install took about seven seconds. Everything between search and
the verify step worked on the first attempt with no friction.

## self-explaining-regression: pass

Inserting `if (!window.confirm('Stop this task?')) return;` into
`handleCancel` turned 7 of 13 tests red, among them
`cancel-not-gated: one activation, one callback, no dialog; repeat activations are no-ops`.
A second `scaffold_pattern` call returned the rule as `MUST_NOT` with the
rationale "Confirmation friction belongs on destructive actions. Cancel is
the safe action — every second spent in a dialog is another side effect
landing." Reverting restored 13 of 13. The test file was not touched.

Friction: the rationale is not in the consuming project. Getting it took a
tool call that regenerates every file.

## accessibility-evidence-pack: fail

Scaffolded `approval-gate` (React): 15 of 15 tests pass, including one
axe-core test.

| Criterion | Result | Evidence |
| --- | --- | --- |
| c1 every listed criterion appears | not-evaluated | The evidence document (step s6) was not written in this run. The contract lists 3.3.4, 2.1.1, 4.1.2 |
| c2 cited tests ran and passed | pass | 15 of 15 |
| c3 criterion-to-rule link comes from the contract | **fail** | The contract does not link them; every mapping was inferred |
| c4 every cited test proves its rule | **fail** | See below |
| c5 no overclaim | not-evaluated | Same reason. The keyboard and screen reader tables are there to build the manual script from |

The rule `controls-accessible` requires approve and reject to be
keyboard-operable with accessible names that distinguish them and name the
action. Its one named React test, `controls-accessible: gate has group role
with aria-label`, asserts the container's `role` and `aria-label` and never
touches either button. axe-core runs in the `proposed` state only, though the
contract has seven states. The implementation may well be correct; the proof
is thinner than the COMPLIANCE table reads. This is what the
`contract-auditor` subagent exists to find, and it has not yet been run
across the catalog.

Also noted: `gate-announced` has no WCAG criterion listed against it. 4.1.3
Status Messages looks like the natural one. That is a judgment for the owner,
not a defect.
